# 拾旅实施计划

## 范围与决策

以 `需求.md`、`交互设计.md` 和 `image.png` 为基线，实现原生微信小程序。P0 主流程为：发现旅行 → 确认 → 查看概览 → Day 2 事件筛选 → 查看事件 → 补写记忆/纠正事实 → 地图联动 → 回忆卡片。采用本机优先存储，不引入无需求依据的登录、后端或数据库。

视觉系统以旅行摄影、黑白纸张基调和橙色“新发现”作为识别，宋体只用于回忆叙事；“旅行轨迹带”同时承载时间与空间信息。

## 垂直切片

1. S01 发现与确认：相册选择、本机检测适配器、候选卡、确认/隐藏。
2. S02 旅程回看：概览统计、路线、Day 卡片、事件时间线和时段筛选。
3. S03 纠正与补充：本地持久化一句话、纠错动作、隐藏事件和数据重置。
4. S04 空间与情绪：原生地图点位联动、回忆卡片与微信分享入口。
5. S05 长期入口：年度时间线、隐私和提醒设置。

## 回滚

所有业务数据仅位于 `shilv_state_v1` 本机存储；“我 → 重置演示数据”可恢复种子状态。源码回滚无需数据库迁移。
